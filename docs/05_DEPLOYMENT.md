# Docker dan operasi
Target Ubuntu VM, existing MySQL container. Compose deployment utama: nginx, app(PHP-FPM), scheduler, worker untuk jobs jika diperlukan. App/scheduler/worker image sama. Tidak ada MySQL baru. Satu database fresh Lab, Laravel migrations membuat tabel.
.env.example: DB_CONNECTION=mysql DB_HOST=<mysql-network-alias> DB_PORT=3306 DB_DATABASE=Lab DB_USERNAME=<dedicated-user> DB_PASSWORD=<set-on-server>; APP_URL, APP_KEY, MYSQL_EXTERNAL_NETWORK, app port, backup settings. Root account disebut saat diskusi tetapi paket tidak membawa password. Pilih least-privileged account pada server. Jangan commit .env.
DB_HOST IP 172.18.0.5 pernah diberikan; fallback configurable, recommended alias stable container pada network Docker eksternal. app/worker/scheduler join network itu; Nginx network internal aplikasi. Dokumentasikan docker network inspect dan docker network connect, verifikasi resolution alias dan koneksi DB tanpa mengubah DB lain.
Mount persist private uploads/storage, public published material strategy, config. Persist file permission nonroot jika mungkin. Host port configurable contoh 8080, konflik port diperiksa. Cloudflare Tunnel dapat mengarah Nginx; domain belum ditentukan. APP_URL HTTPS, trusted proxies sesuai actual reverse proxy untuk secure cookie dan link.
Scheduler tidak duplicate-run beberapa container; job locking/single-run. File SQL upload disimpan tidak dieksekusi.

## Backup
Implement backup database Lab dan file store, job configurable + manual admin trigger, log success/failure. Destination terpisah dari volume utama; target remote belum dipilih (Drive/NAS/off-host future configurable), jangan mengklaim Drive sudah tersambung. Retensi/jadwal configurable dengan initial proposal harian 02:00 WIB dan 7 harian, bukan keputusan pengguna. DB dump account/tool kompatibel MySQL server. Jangan mengirim password pada argumen yang terekspos/log. Encrypt backup jika remote, secret environment. Atomic completion checksum; backup hanya sukses jika dump+files keduanya sukses.
Restore terdokumentasi di lingkungan terisolasi, verifikasi metadata dan sample files; restore produksi bukan tombol tanpa proses review. Hindari mount docker.sock/host root untuk backup. Scheduler backup background agar request HTTP tidak blocking.
Pin compatible runtime image versions saat implementasi. Docker healthchecks Nginx/app; koneksi DB health endpoint tidak bocor credential. Deployment docs install/build/up, migrate non-destructive, bootstrap admin secure, update+backup, rollback app compatibility, restore.
